# Validation

Final clean-install acceptance is in progress on 2026-10-08. No final success is claimed until the corrected profile finishes without guest repairs.

The complete Linux builder extracted Microsoft's Slovenian Windows 11 25H2 consumer x64 media, generated a private local account answer, created the ISO, verified both BIOS/UEFI boot entries and exact answer-file readback, produced its checksum and removed temporary files. An English-only source was rejected before requesting credentials. Four account-generation tests, ShellCheck and embedded PowerShell parsing passed.

The final test has a new blank 64 GiB SATA disk, four CPU cores, 8 GiB RAM, OVMF Secure Boot and TPM 2.0 on Proxmox VE 9.2.3 / QEMU 11.0. Windows 11 Pro without N was selected. Earlier tests exposed a OneDrive setup-stub hang, an interactive .NET restart prompt and protected HKCU writes under normal UAC. The source now bounds actual OneDrive uninstallation, uses DISM /NoRestart and applies six protected user policies to the Default user hive during specialize. Those earlier runs required intervention and are excluded from final clean-install acceptance.

The final profile deliberately displays ordinary username/password fields using DontDisplayLastUserName=1. This setting accepted rr and the configured password in a diagnostic VM; it does not bypass authentication or enable automatic sign-in. That VM also confirmed administrator membership, built-in Administrator disabled, normal secure-desktop UAC, Slovenian display/formats/keyboard/time zone, required apps installed, OneDrive absent and Windows servicing policies/services enabled. A live Windows Update search succeeded and returned five nonoptional updates: Windows Security platform, malware removal, Defender intelligence, .NET security and Windows security. Actual final-profile application launches remain pending.

The separate RustDesk 1.5.0 script was run from the ordinary rr session with normal UAC. First installation returned 0, registered version 1.5.0.29846474, verified its running service and read back allow-remote-config-modification=Y. A second run returned 0 without a second installer directory. Both runs used -SkipLaunch to avoid showing remote-access details. Seven helper/error tests and vendor MSI SHA-256 verification also passed. An upgrade from an older installation and preservation of an actual pre-existing password were not exercised on Windows.

Limits: UEFI optical boot is exercised; BIOS boot has metadata verification only. Missing-app download/retry paths, physical USB boot, activation, ODOS+ web functionality, an actual RustDesk remote session and Ansible/controller onboarding are not exercised. Other Windows editions/releases are not separately tested. Windows cumulative security updates also include reliability fixes.
